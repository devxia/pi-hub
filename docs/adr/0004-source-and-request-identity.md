# ADR 0004：精确源身份与请求核对

Status: accepted

## 决定

所有写入及终端动作以不可混淆的对象和请求身份执行：

- 记录动作绑定 key、物理文件身份、原生 header ID 和源修订，必要时核对父目录/来源根。直接打开前验证完整 v3 header 与文件前后 stat，拒绝悄悄迁移不受支持的源格式。
- 同一 GUI requestId 的启动、名称、Clone、删除及恢复读取原回执；原子认领、协议命令账本和持久结果避免回执丢失后重复副作用。新 requestId 的显式打开仍可启动同一记录。
- 原生名称恢复核对精确追加内容；后来的原生名称优先。Clone 丢失 SQLite 回执时只查询宿主原命令结果，不再次复制。
- 宿主通过私有认证 socket 协议 2、已登记 PID/启动身份/TTY 及 generation/sequence 重新连接。会话切换重新绑定当前原生对象，旧代次或重放报告不能覆盖当前状态。
- 定位、退出及终端关闭在动作前重新核对启动身份和原生终端对象；TTY 号码或窗口标题单独不足以授权操作。

## 理由与结果

用户可以在其他 Pi 中改名、追加、切换或替换文件。文件路径和返回成功不能单独证明当前对象或副作用是否完成。精确身份与原请求核对使失败恢复保持可解释，业务完成和随后刷新失败分别显示。

上述规则不是全局占用策略，不限制用户新的明确打开，不扫描或终止普通外部 Pi。无法证明目标时返回真实错误/未知，不猜测、不自动强杀、不另造副本。
