# Pi Hub 设计简报

## 核心任务

用户从项目范围找到原生 Pi 会话，快速确认上下文，再在外部终端继续。次要任务包括历史选择、归档恢复、重命名、原生 Clone、定位和精确退出 Hub 实例。Hub 管理和阅读，Pi 负责对话与原生记录。

## 工作区

左侧为全部会话、归档及项目导航；底部保留“添加项目”和“设置”。中间为范围标题、搜索/排序/分类工具与两行会话条目。右侧为只读预览、明确的项目/状态及可展开身份。动作集中在行级原生右键菜单，预览没有底部操作栏。

1440×900 参考布局为导航 208、列表 650、预览 582，标题区 40。中等宽度导航 188，工具按受控两行排列；窄窗预览成为覆盖阅读层，背景 inert，Esc 关闭并回到原焦点。深色使用同一蓝灰语义，不更换设计方向。精确取值和组件状态见 [设计规范](../DESIGN.md)。

条目只作视觉省略；完整 SessionID 和文件信息可在详情/菜单取得。状态用文字与颜色共同表达。“会话未连接”不判断普通外部 Pi 的占用。页面最多 50 条，手动拖动和 Option+上下键只改变展示顺序。

## 主要流程

1. **纳管**：选择项目 → 选择历史进入主列表 → 其余归档 → 后台增量发现。范围变更有明确提交/取消，不发布半完成范围。
2. **查阅**：范围/名称搜索 → 单击或 Enter → 首条用户消息与当前分支最近三轮。新导航清空选择；操作或设置保留合理的查阅上下文。
3. **继续**：双击/菜单打开 → 必要时本次终端选择 → 原生 TUI。正常过程没有确认成功的弹窗；目录丢失、真实启动失败或结果未知才提供可行动反馈。
4. **管理**：原生右键菜单针对调用行。归档只改变 Hub 分类，新增对话可自动恢复；Clone 创建新 ID 并切换同一运行时；删除确认明确作用于原文件。
5. **退出**：只列出可控实例；忙碌确认停止任务，正常 Pi 清理后关闭精确终端对象。保留会话与其他标签/分屏。
6. **设置**：Cmd+, 或“设置”打开独立非模态单例窗口。终端/会话存储/Pi 启动按类保存；切换留草稿，关闭/退出保护未保存输入。来源历史选择在该窗口内完成。项目设置和一次性终端选择保持各自上下文。

## 反馈与约束

错误尽量就地显示并保留输入，明确区分业务已完成、刷新未完成和结果未知。恢复核对同一请求，不重复副作用。失败时不自动更换模型、不强杀进程、不删除数据库、不复制会话或凭据。

所有可点击控件有手形、键盘焦点和按下反馈；拖动有抓取手形、方向指示及键盘替代。进入/退出及重排使用短 transform/opacity 动画，系统减少动态效果时关闭。无持续动效和远程字体/图片依赖。

完整业务边界见 [产品规格](product-spec.md)，经验证的实际范围见 [验证记录](validation.md)。
