# Pi Hub 产品规格

本文件定义已确认的完整产品行为。架构理由见 [ADR](README.md#架构决策)，视觉规则见 [DESIGN.md](../DESIGN.md)，已执行检查及其版本边界见 [验证记录](validation.md)。应用内更新尚未实施；其已固化、暂缓实施的设计独立见[更新渠道设计](update-channel.md)，不能按已交付功能理解。

## 1. 职责与数据权威

Pi Hub 是原生 Pi 的中文图形客户端，负责项目组织、会话发现、历史选择、搜索、只读预览、归档及原生命令入口。对话在 Terminal 或 Ghostty 中的 Pi TUI 继续，Hub 不提供聊天输入。

Pi JSONL 是会话 ID、名称、工作目录、消息和分支的权威来源。Hub 使用原记录，不自动镜像，不创建专属对话格式。记录应能由脱离 Hub 的原生 Pi 继续使用。SQLite 保存项目、来源、索引、导入决定、归档分类及自身操作回执；展示顺序属于当前 Hub profile。

Hub 不检测普通外部 Pi 是否使用同一记录，不接管这些进程，不阻止用户新的显式重复打开。用户自行避免并发操作同一记录。已登记 Hub 宿主的状态只用于显示、命令路由及精确终端操作。

## 2. 项目、来源与身份

项目以用户选择的绝对目录区分，默认只包含该目录，可显式包含子目录。路径按词法规范化和目录段匹配，不 realpath 合并符号链接、不做全局大小写折叠。重叠范围归属最具体的有效项目，原记录 header.cwd 决定归属，终端临时目录不改变归属。

默认会话来源为 `~/.pi/agent/sessions`，按 Pi 编码目录布局枚举；自定义来源可选择编码目录或平铺枚举。正常使用无需确认标准来源，不显示常规“待核对/正在核对”提示。读取失败仍须如实显示对象、原因及恢复动作。

多个入口发现同一物理文件只索引一次。不同物理文件具有相同 Pi ID 时标记“会话标识重复 · 部分操作不可用”，限制需要唯一身份的动作，不能任取一个文件写入。名称不承担身份；源物理身份、记录头和修订用于保护准确的操作对象。

移除项目、缩小范围或撤销来源停止对应跟踪/显示，保留分类，不删除原文件。重新纳入时恢复已有分类，仅对首次发现的历史重新选择。其他有效来源仍可提供重叠文件。

## 3. 导入与发现

首次添加项目、扩大范围、新增来源和重新添加项目使用统一历史选择：全部、部分或零条进入主列表，未选有效候选归档。导入只改变管理分类，不移动、复制或改写 JSONL。

候选集由记录身份快照和范围修订确定，不以 mtime 或当前时钟区分历史。选择期间新增记录进入增量处理，原候选更新不会逃离选择。提交前重验候选和范围；缺失候选忽略并说明数量变化。未完成范围不提前发布候选；取消新增项目不提交项目，取消范围变更保留旧范围。中断批次可恢复，不留下半提交分类。

watcher 提供低延迟提示，启动、周期协调及来源恢复补漏。先读 header 并按项目过滤，再读取相关内容。部分尾行等待后续扫描，完整坏行单独报错；截断、重写或身份变化重建该记录投影，不盲目沿用字节偏移。

只有来源根身份可信、完整枚举成功，且对缺失记录再次确认不存在，才能清除条目及分类。权限失败、磁盘未挂载、取消或部分扫描不能推断删除。确认移走或删除后再次出现的记录按新发现处理。

首次消息保存后新会话自动进入主列表，空 header 不产生条目；Hub 退出期间保存的新记录在重启后补齐。归档后新增可见用户/助手对话自动恢复；名称、工具事件、其他元数据或旧消息重扫不触发恢复。

## 4. 浏览、预览与展示顺序

浏览、导入、搜索、预览、归档和恢复无需配置 Pi 或安装扩展。范围包含全部会话、单项目及归档；搜索覆盖名称、首条用户文字形成的显示标题、项目名和路径，不提供正文全文检索。排序支持最近对话、名称、创建时间及手动排序；最近对话依据消息时间，改名/归档不置顶。

单击或 Enter 预览，上下键移动焦点，Cmd/Ctrl+F 聚焦搜索。预览显示当前分支首条用户消息和最近三轮用户/助手可见对话，重复命中只显示一次；工具输出和思考不显示，附件无文字时提供中性说明。已连接宿主提供活动 leaf；未连接时使用原生 Pi 从文件恢复的分支语义，不把缓存或其他进程内存选择当权威。使用只读解析/内存投影，不因浏览迁移源文件。

长内容可展开，身份区可滚动，正文使用剩余空间。会话文本只作惰性文字，不执行 HTML、脚本或命令，不加载远程图片。

每页最多 50 条。拖动或 Option+上下键只调整当前页展示顺序并切到手动排序，筛选内移动保留其他会话相对顺序。顺序按 profile 的 localStorage 保存，上限 20000 个键；重开后选择手动排序可继续使用，排序模式本身按原默认重新开始。该顺序不改消息、文件时间、分类或运行状态。

导航范围变更清空选择并关闭预览；管理动作、设置和可恢复失败保留合理的查询、排序、选择、输入及滚动。分类后可保留当前预览并说明其所在范围；操作其他行不抢占当前预览。

## 5. 两行条目与行级操作

条目首行左侧名称、右侧项目名；第二行左侧状态、右侧日期时间。长名称仅视觉省略，不修改真实值。条目不显示 SessionID/JSONL 文件名；预览详情提供项目、记录目录、完整 ID 及必要的本次运行信息。预览没有底部按钮区或预留空白。

原生 macOS 右键菜单支持右键、Control 单击和 Shift+F10，固定作用于调用行的 key/identity。菜单提供打开、可用时定位、重命名、**复制并切换…**、归档/恢复、复制完整 SessionID、在访达中显示文件、可控实例退出和删除。取消不执行；实际命令前重新验证对象及能力。危险删除分组并再次确认。

运行文字统一使用：

- 会话未连接
- 会话已开启 · 空闲
- 会话已开启 · 处理中
- 已归档
- 会话标识重复 · 部分操作不可用
- 记录暂不可读 · 显示缓存

“未连接”只描述 Hub 控制连接，不证明普通外部 Pi 未打开记录。状态同时使用文字，不能只靠颜色。

## 6. 启动配置与终端打开

Hub 自动从有效 PATH 入口及常见安装位置发现 Pi 与 Node 24+，已有显式配置继续生效。正常打开不要求填写路径或先保存设置；设置保留实际检测后的手动排障入口。GUI 不依赖 shell alias。外部宿主与包内 SDK 当前统一验证 Pi 1.5.2；新验证使用官方最新版本，不降级用户 Pi。

外部终端运行独立 SDK 宿主与官方 InteractiveMode，通过用户交互登录 shell（`-ilc`）继承导出环境，保留 PATH、用户扩展、模型、包、项目资源和信任规则。凭据只在进程环境中传递，不序列化到 Hub 数据/启动描述。不要求 Hub 全局扩展；保存启动配置时只清除精确登记的 Hub 扩展配置项，保留其他 Pi 设置。

无默认终端时列出实际安装且受支持的 Terminal/Ghostty，默认不勾选“以当前选择为默认终端”。勾选保存，未勾选仅本次使用；取消不启动、不保存。选择后自动继续原请求。Terminal 新窗口，Ghostty 新标签页，无窗口时可创建承载窗口。

双击或菜单打开使用原记录。新建在明确项目目录打开 Pi，不预先命名、不创建 Hub 占位记录；全部会话视图中新建先选择项目。同一次请求核对不重复启动，用户新的明确打开允许新实例。“定位 Hub 终端”是独立动作，核对 PID、启动身份、TTY 及原生对象。

正常打开、连接和定位没有进度/成功确认框；后台核对原请求，真实失败或需人工恢复时提供错误、重试/核对及手动命令入口。原 cwd 确认丢失后，可显式选择可用的已纳管目录仅本次继续，或取消。原 ID、JSONL、header.cwd、项目归属保持，下次仍按原目录确认。

## 7. 名称、Clone 与删除

**名称**对应原生 `/name`。连接宿主调用 AgentSession.setSessionName；无已连接宿主时通过公开 SessionManager 写入原生名称事件。允许中文、重名和清空，清空恢复自动标题。操作前核对精确文件身份及修订；回执恢复不能覆盖之后发生的新名称。

**Clone**仅在用户确认“复制并切换…”后执行原生 `/clone` 等价入口，从当前宿主活动 leaf 创建新 ID 并切换同一运行时，原记录保留。不预先要求副本名。未连接记录先正常打开，再复制；忙碌或用户扩展取消如实反馈。复杂分支、压缩与上下文编辑按 Pi 原生语义处理。同请求核对只读取原结果，不再次复制。

**删除**明确作用于原始 Pi 文件。确认需说明优先废纸篓、失败时永久删除；用户自行退出使用记录的其他 Pi，Hub 不检测或终止它们。删除前后核对文件、父目录及来源根，拒绝删除替换对象；两种方式均失败则保留条目和错误。源删除不级联删除独立副本。已完成与刷新失败分别反馈，刷新重试只读取。

## 8. Hub 与宿主生命周期

关闭主窗口仍保持后台跟踪，可由 Dock 重开。Cmd+Q 退出管理器，仅断开控制连接，外部宿主继续运行；下次 Hub 启动重新认证已登记宿主。

菜单“退出会话”只在存在可核对的控制实例时显示；多个实例分别选择，不默认全部退出。忙碌时确认“停止当前任务并退出”，取消不停止；空闲实例正常退出。核对 PID/启动身份/TTY 后发送正常 SIGTERM，由 Pi 停止当前任务并完成扩展及终端清理，再关闭精确标签页/窗格。保留原记录、列表条目、其他实例、标签页及分屏。结果未知反馈未知，不自动强杀。退出等待不阻塞管理读取队列。

## 9. 统一设置

左下角为“添加项目”和“设置”；应用菜单“设置…”及 Cmd+, 打开同一个独立非模态窗口，标题“Pi Hub 设置”。主工作区可继续操作，再次调用激活现有窗口。同次运行重开记住类目。

类目为“终端”“会话存储”“Pi 启动”。终端/Pi 按类保存，跨类保留草稿；Pi 路径编辑使旧检测失效，只有实际检测通过才能保存。成功留在当前类目并局部提示。关闭、Cmd+W 或退出有未保存输入时选择“继续编辑 / 放弃更改”；提交未定时先完成或恢复操作。

来源添加、历史选择、取消/恢复及移除确认都由设置窗口承载，明确确认后立即生效，主工作区同步且保留合理上下文。右侧表单滚动，导航/操作区域稳定。项目设置仍属于当前项目，一次性终端选择仍属于打开流程。

## 10. 持久化、安全与性能边界

应用名 Pi Hub、包名 `pi-hub`、bundle ID `local.pi-hub.desktop`。默认数据根 `~/.pi-hub` 包含数据库、启动设置、宿主回执及 Electron 缓存/日志/崩溃文件；显式 `--user-data-dir` 优先。原生会话和 Pi 设置保持自身位置。

SQLite 由 utility 单写入者持有，使用事务及版本迁移，迁移前保留可恢复备份。损坏或不可访问保留原库和分类，不自动删库重建。renderer sandbox/contextIsolation 开启、Node 集成关闭，preload 白名单与精确窗口/主 frame/URL 校验；设置仅获其所需偏好和来源权限。原生终端、目录选择及废纸篓由 main 处理。AppleEvents 许可由用户决定，不重置 TCC。

缓存先显示，后台逐步协调；读取并发上限 4，watcher 待处理路径上限 256，超限转完整协调，避免无界队列。预览按需读取；无变化心跳不重写 SQLite、不发布全量工作区。目标规模约 50 项目/10000 个非空会话，普通新增与改名显示延迟 p95 目标约 2 秒；这是验证目标，当前版本实测范围以验证记录为准，不能用历史结果承诺每次延迟、内存或帧率。

交付为可离开开发服务器运行的 macOS .app，分别支持 Intel（x64）与 Apple Silicon（arm64）构建，默认输出到被 Git 忽略的 `dist/packages/`。每个包采用目标 CPU 的 Electron 与所需原生依赖；构建验证和实机认证分别记录。已完成实机验证范围为 macOS 15.7.7 Intel、Pi 1.5.2、Node 24+、Terminal 2.14、Ghostty 1.4.0；Apple Silicon 实机结果及其他平台/版本、iTerm2、tmux/screen/SSH 定位、签名公证、安装器和自动更新不在现有认证范围。内置 llama.cpp 不能由当前公开 SDK 组合完整提供时明确失败，不静默换模型。
