# 远端服务器与任务工作区

状态：已批准的产品契约，覆盖 M1/M2/M3 与 Slurm/普通 Linux。远端任务独立于原生 Pi Session；实际验证范围见验证记录。

## 1. 要解决的问题

Agent 对话可以完成远端工作，但连接信息、上传路径、调度 JobID、日志和结果往往散落在工具调用里。换一次对话、重启本机或断开网络后，用户需要重新询问进度；“暂时没拿到状态”也容易被误解为“任务停了”。

Pi Hub 提供独立的「远端任务」工作区，统一保存服务器、任务及每次运行的对应关系。Agent 继续负责写代码和分析结果，Pi Hub 负责可靠地登记、观察、提交与取回。原有 Pi 会话列表保持原用途；远端作业不是一种 Pi Session，二者通过可选关联连接。

## 2. 首期与后续范围

首期同时完成 **Slurm 作业与普通 Linux 后台任务** 两条闭环，共用服务器、输入清单、日志/进度、结果取回和 Agent 接口，执行身份与取消机制由各自 adapter 处理。不能把普通 Linux 只做成“可登记服务器但不能运行任务”。登录优先使用用户已有的免密 SSH 配置，同时支持手动添加服务器；不以安装某个 Skill 为前提，见第 4 节。

| 阶段 | 用户可以做什么 | 阶段验收后是否可单独使用 |
| --- | --- | --- |
| M1：服务器与已有任务观察 | 验证信任与能力；登记 Slurm 完整 JobID，或 Linux PID/运行目录及日志；明确已有任务的观察范围 | 可以，观察已有任务，不创建计算任务 |
| M2：两类提交与取回闭环 | 审核并上传；Slurm 提交作业、Linux 受管后台启动；查询、取消、取回结果 | 可以，两类服务器均有 GUI 操作闭环 |
| M3：Agent 联动 | Pi、Kimi 等通过同一接口登记/查询两类任务或申请提交 | 可以，GUI 与 Agent 使用同一身份和状态 |
| 后续单独评估 | 作业数组和复杂 DAG、系统服务部署、脱离受管运行边界的任意后台守护进程、长期本机常驻监控 | 不计入首期通过范围 |

**本契约的首期范围包含 M1、M2、M3，且每批覆盖两类服务器**。不能把仅完成 M1 的服务器面板宣称为首期交付。M2 完成 GUI 闭环，M3 完成 Agent 联动；各批沿用相同的任务/请求模型。Slurm 首期只写入/取消单个作业，数组与 federation 标识能识别但不能截断 ID 后取消整组。Linux 首期支持受管的 Python、shell、CPU/GPU 计算任务，要求实际工作负载在包装器下以前台方式运行；由 Hub 负责后台化，不在用户脚本中再套 nohup、双重 fork 或 daemonize 逃离跟踪范围。已有 nohup 任务仍可只读登记。

本期不做远端桌面/完整 SSH 终端、云服务器购买、多人调度服务、任意历史聊天的自动解析、自动安装 CUDA/ROCm/Conda/软件包、自动更新远端环境、自动同步整份工程覆盖本地，也不实现已另行冻结的应用更新渠道。

## 3. 界面与主要操作

主窗口侧栏增加「远端任务」。进入后使用现有 Clear Order 变量与三栏结构：左侧服务器和过滤条件，中间任务列表，右侧选中任务详情。分隔线调整相邻栏宽，远端宽度单独记忆。窄窗详情为原生弹层，保留内容、背景 inert、Escape 关闭与焦点归还。栏宽限制和键盘操作见[工作区与组件](../DESIGN.md#工作区与组件)。

- 服务器：显示昵称、连接状态、最后一次成功观察时间和可用能力。操作为添加/编辑、验证连接、查看能力、停用。停用不取消作业，不删除远端目录；有活动任务时记录仍保留。
- 列表：任务名称、服务器/项目、调度状态、阶段或可信百分比、更新时间。提供全部、排队、运行、结束、需要处理等过滤。
- 详情：概览、日志、指标、文件、操作记录。明确区分任务状态、连接状态和文件传输状态。保留关联会话入口；外部 Agent 的关联仅是来源标签，不承诺打开 Kimi 的私有链接。
- 新建任务：选择服务器 → 本地输入与远端目录 → 脚本/环境/资源 → 审核清单 → 上传并启动。Slurm 表单显示 partition、account、QoS、时限等；Linux 显示工作目录、解释器/启动脚本、环境、GPU 选择和实际支持的限制。审核显示文件数量/总大小、远端目标和运行方式；启动后转为观察，不重复点击重试提交。
- 已有任务：Slurm 输入完整 JobID 并核对 owner、cluster、submit time；Linux 输入 PID/运行目录及明确日志路径，核对用户、boot ID、进程启动身份等。两类外部已有任务首期均只读。Linux 进程消失只代表不再可见；没有可靠退出回执时显示结果待核对，不能猜成功。
- 结果取回：选择具体产物/子目录，下载到本地独立结果目录；冲突时询问覆盖或另存。传输成功与计算成功分别显示。

服务器侧栏顶部放本地会话返回入口与更多操作，Agent CLI 位于更多操作中。无服务器时直接显示添加和 SSH 别名导入入口。有服务器时，标题旁的「＋」提供这两项操作，下方按名称或主机筛选列表。条目两行显示名称和 Linux／Slurm 与主机，长名称可悬停查看。搜索无匹配时可清除查询并继续搜索，服务器列表独立滚动。

服务器管理放在该工作区内，避免把运行中的任务塞进设置窗口。设置只在需要全局轮询/缓存策略时增加一小节；既有终端、存储、Pi 启动三页及其草稿关闭保护照常工作。

## 4. 服务器、认证与能力

服务器资料保存显示名、主机/端口/用户、可选跳板、登录方式引用、远端工作根、默认环境及执行类型（Slurm / 普通 Linux）。Slurm 保存调度默认参数，Linux 保存允许的线程/GPU 环境值；CPU/GPU 硬配额不在普通 Linux 承诺内。路径/资源是可修改的默认值，每次提交仍保存不可变的实际值。修改资料不会把历史任务悄悄改指向新主机。

使用系统 OpenSSH，支持已有密钥、ssh-agent、证书及受控跳板。后台轮询使用非交互连接和明确超时，可复用终端已经配置的免密认证。导入 SSH 别名后，由 Pi Hub 根据核对过的字段建立独立连接配置。

「导入 SSH 别名」提供「使用默认 SSH 配置」，点击后直接预览当前用户 `~/.ssh/config` 主文件中的别名。也可以通过「选择 SSH 配置文件…」或粘贴片段后预览。选中别名会打开服务器表单供用户核对连接地址、跳板和认证字段，随后显式保存为独立服务器记录。导入采用静态读取，保留适用配置的第一个单值声明，并报告无法解析的项目，具体范围见第 9 节。

认证过期、agent 未解锁或配置变化时显示「需要重新登录或检查配置」，停止重复连接并允许用户修复后重试。首期不新增保存明文密码、自动代填验证码或任意登录脚本；用户未要求这些路径，不能宣称已支持。工作负载、公开文档和数据库不存私钥内容、密码或 agent 凭据。

不直接执行从聊天或远程返回的完整登录命令。显式字段先验证，生成受控连接配置。可选择导入 SSH alias 的安全字段，但不执行 `Match exec`、`LocalCommand`、`KnownHostsCommand` 或任意 `ProxyCommand` 来“读取配置”；首期跳板使用受控 ProxyJump。无法安全解释的配置交由用户改为明确字段，不声称支持所有 ~/.ssh/config 写法。

实际 SSH RPC 的控制、输入/结果字节传输及每一跳都显式使用同一份受控配置，排除默认用户/系统配置、非预期 ControlMaster 复用、agent/X11/端口转发、执行钩子和额外 known_hosts 来源。不得只在导入界面过滤、连接时又回退读取全局配置。每一跳独立核对主机信任，全部信任确认完成后才进行远端能力探针。

本地参数数组不能保证远端 argv 原样传递：SSH 命令仍可能经过远端 shell。因此控制路径采用固定、经过审计的远端入口，通过有长度限制的标准输入传递结构化请求；少量必须进入远端命令文本的安装路径/版本按明确引用规则处理，拒绝不支持的换行/NUL 等输入。Slurm 资源参数为允许清单，不接受可替换脚本、输出路径或执行语义的任意透传参数。用户审核的工作负载脚本与这些控制参数分开保存。

首次连接可发现候选公钥及 SHA-256 指纹，或显式选择 known_hosts 导入，要求用户通过已知渠道核对后信任；候选不等于已信任。发现首跳不认证；发现后续跳只通过已经信任的前置跳，绝不向未信任目标认证。密钥变更必须阻断。不得自动设置 StrictHostKeyChecking=no、丢弃 known_hosts、自动接收变更。Hub 管理的信任记录存入当前 profile，不静默改用户全局 SSH 配置；既有可信记录可显式导入。

能力检测采用固定、只读、有限输出的命令，检查 SSH 身份、OS、Python 3、工作目录权限、磁盘、传输工具，以及所选执行类型的能力；不自动安装依赖。Slurm 检查调度命令/输出，登录节点只做轻量管理。Linux 检查 /proc 启动身份、受管 supervisor、会话/进程组隔离、可用的 pidfd 与资源限制；“python3 存在”不代表这些全部可用，必须分别探测和验收。还要验证服务器退出登录后的进程保留策略；setsid/nohup 本身不能绕过服务器清理登录会话的政策。

CPU/GPU/DCU、partition、account、QoS 由实际能力决定，不能把某技能中的机器配置当通用事实。Linux 的 GPU 设备选择/CPU 线程数是运行参数，不冒充 Slurm 排队、独占分配或硬性配额；有支持的 cgroup/rlimit 才展示相应可执行限制。不替用户抢占其他进程或修改系统策略。检测结果带时间、来源和失效状态。

## 5. 任务身份与状态

| 记录 | 用途 |
| --- | --- |
| Server | 本地服务器 ID 与连接资料 revision；身份变化后需重新核对 |
| Task | 用户看到的逻辑任务、可选 projectId/会话来源、输入/产物声明 |
| Attempt | 一次不可变的运行：服务器身份快照、脚本/输入摘要、资源、远端唯一目录、类型化执行引用（SlurmRef / LinuxRef） |
| Operation | 上传、提交、取消、下载的请求 ID、授权摘要、执行进度和最终回执 |
| Observation | 带来源、时间和序号的调度/日志/指标采样，不覆盖确定的终态 |

重跑产生新 Attempt。SlurmRef 至少绑定服务器/cluster、用户、完整 JobID 与提交时间；存在 SLUID/DBIndex 时一并记录。LinuxRef 绑定服务器身份、用户、boot ID、supervisor 与工作负载的 PID/启动时钟、专属进程组、Attempt/executionId 及控制端点代次。不能只按数字 PID 或 JobID 路由操作；日志目录也不是取消权限。服务器重装/重启、主机密钥变化、ID 重用、所有者不符时，停止写操作并要求核对。

逻辑任务是可编辑草稿；Attempt 的持久状态为 unknown、queued、running、cancelling、succeeded、failed、cancelled，分别表达结果待核对、排队、运行、取消中和权威终态。Operation 独立记录 preparing、review、approved、running、done、unknown、denied、blocked、expired；本机预检明确阻止且尚未进入远端边界时是 blocked，可能已有副作用时才是 unknown。取消请求另有「取消中」，只有执行 adapter 的权威终态证据才变为已取消：Slurm 的调度终态，或 Linux 控制者保存的取消动作与受管范围结束回执。接受取消或信号发送成功均不等于已取消；任务可能在取消前已经自然完成。连接状态独立为可连接、离线、认证失效、信任待处理；任何离线都保留最后已知任务状态与观察时间，不改成失败。

Slurm 以 squeue 查询活动状态/排队原因，以 sacct 查询终态及退出码，保留原始状态方便排查。队列里消失不代表成功；accounting 延迟、未启用、不可访问或记录过期时显示结果待核对，可使用本次运行目录里已校验的退出回执辅助判断。当前官方文档的新字段/JSON 选项必须能力检测，不能要求用户集群已经升级到文档最新版。

Linux 没有调度器时从准备中进入运行中，不虚构集群排队状态。由本次运行的 supervisor 保存启动回执、真实 wait/退出码及完成记录，重连优先读同一 executionId 的记录。仍有受管子进程时显示收尾中；退出码为零但执行范围尚未结束，不能提前报成功。supervisor 丢失、进程消失却缺失退出回执、服务器重启或身份无法核对，显示结果待核对；不能用 kill -0、日志中的“done”或 result 文件存在来断定成功。已有外部进程没有受管回执，只提供身份匹配期间的存活/日志观察。

进度分三层：文件准备与传输；调度状态与耗时；应用报告的阶段与计数。操作记录分别展示已固化的本地输入字节、已完成 SFTP 批次的确认字节和已校验并原子发布的本地结果字节。中断保留最后确认的累计字节，未确认批次不计入。只有应用给出合理的 completed/total 或受信任的结构化进度，才显示百分比。GPU 利用率、日志行数、时间推算不冒充完成百分比。任意旧日志只能显示文本/阶段；预计结束时间仅在依据充分时显示并标注估算。

首期支持有大小上限的原子替换 progress.json，字段包含 schemaVersion、attemptId、executionId、sequence、updatedAt、stage、completed/total、metrics。Linux 的 receipt.json 由受控 supervisor 保存，包含 Attempt/执行代次、类型化引用、真实主程序 wait 状态和 scopeEnded；Slurm 终态由 controller/accounting 的完整执行身份确认；工作负载主动写出的“完成”只算应用报告，不能单独证明成功。允许字段缺失，不把缺失补为成功；100% 也不自动转成功。已有项目可在任务编辑器显式映射受允许结果 JSON 的 stage/completed/total/metrics 属性路径；同样有 16 KiB、有限数值和最多 16 个指标限制。映射由本机绑定当前 Attempt/executionId 和观察序号，不接受业务 JSON 自行指定执行权威。100% 仅是进度，仍不能改变执行终态。

计数必须有限、非负且 completed 不大于 total；百分比只描述当前 stage，换阶段可以重置。sequence 只在同一 executionId 内比较；另记本机接收时间，不以服务器时钟倒退决定新旧。检测到 Slurm requeue/restart 或执行代次不明时，使旧进度/退出回执失效，直到新执行身份确认；首期不提供自动重新排队。调度状态与控制回执矛盾时保留两者并标为待核对。包装器与用户工作负载属于同一远端账户，不宣称能抵御该账户恶意伪造回执；Hub 不能把结果文件当作新的命令或权限来源。

## 6. 提交、传输与恢复

每个 Attempt 使用专属远端目录，保存版本化清单、启动脚本、输入摘要、日志、提交回执和退出回执。控制文件权限收紧；目标路径不能包含越界、路径穿越或被替换的软链接。原始用户脚本是被审核后显式执行的工作负载，不与主机名/路径字段拼接成一条 shell 字符串。

上传用明确清单和排除规则，默认排除 .git、.scratch、依赖缓存、密钥、环境凭据、旧输出；忽略规则不等于安全保证，审核清单才是本次传输边界。首期默认拒绝输入中的符号链接和特殊文件，核对实际读取对象与父目录链，不能仅在预览时做一次 realpath。外部数据必须显式选择纳入清单；大数据优先引用远端已有数据，避免重复传模型。上传进入临时目录，完成校验后只发布到本 Attempt 独占目录，不合并覆盖旧运行；取消不留下可误提交的半份输入。

首期以系统 OpenSSH SFTP 为字节传输基线，JSON 只承载有界控制信息；rsync 可作为未来的可选加速路径，不做隐式删除同步。每次递归清单最多 10000 个文件及目录，总字节最多 1 TiB，单次读写缓冲 256 KiB；这些限制在审核前明确检查，不把科学输入装入 base64 JSON。SFTP 通过同一逐跳受控配置进入固定对象子系统，只能读写私有票据声明的编号对象，不能访问任意远端路径、修改元数据或跟随软链接。上传后重新核对实际字节数与 SHA-256，再从独占 staging 原子发布 Attempt；下载先固化远端结果子目录的私有快照，逐文件校验后原子发布本地独立目录。中断只停止本机传输并释放对象票据，不生成远端取消或发布半份 Attempt。失败的未发布 staging 可保留供人工复核，不会自动提交。审批后传输已固化的私有输入快照，原文件之后改变不会替换已审核的字节；用户要使用新内容必须新建审核和 Attempt。取回默认另存；覆盖审批绑定具体目标修订与父目录身份，发布前再验，新出现的冲突/替换不能沿用旧审批覆盖。路径和软链接约束覆盖实际打开与最终发布过程。

Slurm 提交采用以下顺序：

1. 本机先持久保存请求 ID、Attempt 与用户审核的参数/文件摘要。
2. 远端唯一目录写入准备记录，通过经检测支持的锁/原子文件操作保证同一 Attempt 不被并发提交。
3. 版本固定的用户目录小工具调用 sbatch --parsable，把可用的 Attempt 关联标记和运行路径写进调度提交；工具不常驻、无需 root，不是新的远端平台服务。
4. 成功后持久写入完整 JobID、身份与回执，再返回 GUI；GUI/Agent 超时重连先查询原请求。

必须承认 sbatch 接受作业、远端回执落盘之间存在不能靠本地事务消除的断点。SSH 断开后不能保证“恰好提交一次”，也不能直接重发 sbatch。通过关联标记、用户、路径、远端 staging 时间窗口查询队列/历史；不把本机/服务器时钟一致作为前提。唯一匹配才恢复绑定。只要提交是否被接受仍未知，零匹配即使查询成功，也不证明可安全重提；零匹配、历史不可查或多个匹配都保持结果待核对，禁止自动再次提交。用户若确实决定再运行，应创建新 Attempt，并看到可能重复的提示。

### 普通 Linux 的受管后台启动

1. 先持久保存本机 Operation/Attempt、审核摘要和远端独占目录。在任何可能启动工作负载的进程创建之前，远端以独占锁写入不可逆的 launch-intent，绑定 Attempt、executionId、请求 ID 与输入摘要：临时文件 fsync、原子发布、父目录 fsync 完成后才允许继续。目标文件系统的锁/持久化能力必须验证，不满足时禁止受管启动。
2. 只有持有该次创建权的 runner 可以把一次性启动权交给新 supervisor；它继承并接管专属锁/启动通道，在持久确认身份和私有控制端点后才启动工作负载。并发请求和重连只读现有意图/回执，不因锁释放、端点消失或 PID 不存在重新创建控制者。意图存在却缺回执即结果待核对；若用户决定再跑，必须新建 Attempt 并提示旧工作负载可能仍在运行。
3. supervisor 为**仅随本次任务存活的控制进程**，与 SSH 通道分离、关闭 stdin、输出进入专属日志。它创建专属会话/进程组中的长寿命组长 helper，由 helper 在前台启动实际 Python/shell 工作负载。控制者和 helper 均在启动后代前设置 Linux child subreaper；无需 root 或全局 daemon。helper 等待实际主进程和归属它的孤儿后代，主进程先退出时仍保留组长，不把剩余子进程丢弃。
4. 记录分为启动回执、主进程退出记录、整个受管范围完成回执。helper 用真实 wait 状态记主进程退出，并持续回收归属它的子进程，只有内核返回 ECHILD 才报告范围已结束并退出。控制者通过 waitid(WNOWAIT) 暂存 helper 的退出状态，禁止其他线程或 Popen.poll()/wait() 提前回收它；支持时同时持有 pidfd。正常完成要收到匹配 executionId 的范围回执，并核对控制者也无残留后代；缺任一证据不报成功。
5. 仅在已确认服务器允许该运行方式脱离登录会话存活的前提下，SSH 或 Hub 退出后任务继续。本机再开时查询原 Attempt。只读配置探针不等于存活验证，需按下述能力门槛完成授权的实际检查。

取消通过仍存活的控制者验证同一 Attempt、executionId、取消 Operation ID、审批摘要及端点代次，再向自己的专属进程组发送 TERM。组长 helper 保持存活并接收控制信号而不抢先退出，实际工作负载恢复正常信号处置；取消、退出检测和回收由同一状态机串行处理。主进程结束但后代仍活着时保持收尾中/取消中。不能通过 /proc children 或一次进程列表扫描判定整个范围为空：该接口在并发退出时可能漏项；内核 wait/ECHILD 才是已接管后代的回收依据。禁止忽略 SIGCHLD、使用 SA_NOCLDWAIT 或另一路自动回收破坏这些条件。

TERM 超时仍未结束则报告事实，强制结束需要新的独立审批。发送组 KILL 前先持久记录该取消动作；helper 身份仍存活或尚未回收，不能对已复用的 PGID 发信号。KILL 发出后关闭进一步的组信号入口，回收 helper，再由控制者作为 subreaper 等待已接管后代全部退出，直到 ECHILD 才写范围结束；存在不可中断进程就继续取消中，不能把 KILL 返回成功写成已取消。控制者或 helper 非预期丢失且无可靠范围回执时保持待核对，不重建控制权、不按旧 PGID 重发。pidfd 保护具体进程引用，**不等于**任意进程树/cgroup。

Linux 取消回执保存取消 Operation ID、持久动作记录、实际信号结果、主进程原始 wait 状态（若可得）及范围结束事实。动作执行前已有自然完成回执则保留自然终态，取消记录为未执行；动作执行后原始退出证据与取消竞态不能区分时，分别展示“范围已结束”和“结束原因待核对”，不捏造取消因果。原请求恢复先查回执；动作记录已存在但是否发信号未知时不自动重复。范围未结束或控制者丢失时不得报已取消。

基线承诺限于不自行 daemonize、切换会话/进程组、创建新的 PID namespace 或逃离受管范围的计算脚本及正常后代。能力验收覆盖 fork/退出竞态、组长先退、孤儿后代、PID/PGID 复用、控制者与 helper 崩溃；无法满足则不开放对应控制能力，不能以 nohup 加 PID 文件替代。默认不要求 systemd --user、root、容器或联网安装依赖；systemd transient service/cgroup 仅为未来可选后端。

登录退出保留能力为「已确认允许／已知禁止／未确认」，带主机身份、策略证据和验证时间；后两种不能显示已验证受管启动能力。授权验证需覆盖启动 SSH 连接结束、适用的最后登录会话退出及已知延迟清理周期。不能为测试退出用户其他真实会话，应使用自有测试账户/环境或协调明确测试窗口；条件不足就保留未确认。策略变化后失效重验，Hub 不修改 PAM/logind/管理员策略，也不静默降级。

环境使用明确的解释器路径/初始化脚本与工作目录，不假设交互 shell 的 conda activate 在非交互 SSH 中可用。环境准备为单独显式工作，不在提交按钮中隐式联网装包。远端不能联网时允许使用已有环境或事先准备的输入；网络能力未知不自动修复。

### Slurm 的受约束取消

取消不仅在查询时核对身份，还必须在调度器执行动作时约束对象。首期仅向 Hub 提交、带唯一 Attempt 标记的单作业开放取消：优先使用实际版本支持的稳定 SLUID；或经测试证明由控制器同时应用的完整 JobID、owner、cluster 与唯一 job name 过滤条件（如受支持的 scancel --ctld 组合）。本机显示名与唯一调度名分开；标记用于关联，不能被当作对同一账户恶意伪造的安全凭据。若版本、federation、标识/过滤能力不满足契约，则该作业只读，不能退化为“查一下再按数字取消”。已有外部作业首期一律只读登记。

取消命令被接受只显示取消中，随后查询最终 CANCELLED/COMPLETED/其他状态；取消与完成竞态不倒写终态。同一取消请求恢复先查结果，不无条件再发。首期不从日志文本生成 kill/pkill/scancel，不批量终止用户所有任务。取回采用允许路径内的产物清单、临时文件和完成校验，拒绝越界软链接/绝对路径和自动展开的不可信归档；不自动执行下载的文件。

## 7. 与 Agent 的关系

**Pi Coding Agent 是默认联动入口。** 在「远端任务」的任务详情点击「在 Pi 中打开」，Hub 用该任务的本机项目目录启动原生 Pi，自动关联该任务。从会话列表打开的 Pi 首次使用远端任务工具时，在 Pi 的选择器中确认一个任务。同一个运行中的会话复用这项关联，切换原生会话后重新选择。工具 `pi_hub_remote` 提供关联任务的摘要、执行状态、有限日志与操作回执，也能发起提交、取消和取回申请。原生联动复用 Hub 已有的 Pi 启动配置，无需创建 CLI 启动器或授权文件。用户全局 Pi 配置和 Skill 不参与注册。

**其他 Agent 和从 shell 独立启动的 Pi** 可以使用本机 `pi-hub-remote` CLI。用户仍可直接登记已有 Slurm JobID 或 Linux PID、运行目录及日志，由 Hub 只读观察。聊天内容和终端文字不提供可靠的提交身份与回执。

原生工具通过 Hub 已登记的 SDK 宿主连接查询。Hub 按当前会话、任务 ID、项目和服务器核对范围。CLI 则通过当前 profile 的私有 Unix socket 通信，凭据带范围、有效期且可撤销。两条入口共用远端 worker 和操作记录。SSH、传输和数据库写入由 Hub 服务管理。Hub 停止时，两条入口都返回服务不可用，保留已有操作以便核对。

已关联任务的状态和有限日志可重复查询。提交、取消和取回均生成待审操作，在 Hub 的「待审与近期操作」中核对后批准。GUI 审批由服务端绑定不可变摘要，Agent 后续改参数使审批失效。同一主体用相同 requestId 和绑定参数重试时返回原操作及其状态。更换主体、命令、任务或服务器修订需要新 ID。输入原文件变动后，同一 ID 仍查询原快照。准备失败或过期后需新建审核。

访问凭据由用户在 Hub 授予、限定时效并随时撤销，绑定具体 profile 和以下范围；CLI 不能自行扩大授权，也不通过命令行参数泄露凭据。

| 接口 | 最小范围 |
| --- | --- |
| server list / capabilities | 返回授权服务器与能力摘要，连接路径和认证资料留在 Hub |
| task adopt / prepare | 限指定服务器及项目，登记返回执行 ID 与只读状态，准备返回操作 ID 与进度 |
| task status / logs / operation status | 指定 Task/Attempt/Operation，日志只允许有界 offset/长度，不接收任意远端路径 |
| submit / cancel / overwrite | 对象范围内还必须存在 GUI 批准的有效请求摘要 |

Hub 未运行时首期 CLI 返回服务不可用，不另起数据库写入者。用户打开 Hub 后可以用原请求 ID 恢复查询。

可关联 Pi 原生 headerId/物理源身份，也可记录来源 kind=external、外部不透明 session ID。这些只是导航/审计字段，不是权限凭证；本机原始会话、凭据和登录命令不会写入公开仓库。不会自动修改用户全局 remote-compute skill 或给 Kimi 安装插件。

## 8. 本机架构与存储

当前 `BackgroundSessionManagement` 的常规请求 15 秒超时，`utility.ts` 的常规管理命令经串行链，已有预览 I/O 和退出等待的特定例外。SSH/上传不能放进这一常规串行链。

采用独立 remote utility worker，管理连接、并发与远端操作。IPC 在校验并持久登记 preparing 后返回 Operation ID，异步固化输入，再更新为 review、blocked 或 expired。用户按同一 ID 查询，审批仅接受完成清单的摘要。审核界面按 ID 和摘要分页核对文件路径、大小和 SHA-256；默认工作区只读取有界的近期历史与待处理摘要。慢网络只占自己的连接任务，不占 SQLite 事务或现有会话服务。超时取消本地观察/传输不等于远端计算已取消。

远端模块使用当前 profile 下 `remote/remote.sqlite`，由单一 remote worker 写入。复用现有“版本检查→SQLite backup→事务迁移→失败保留原库”的原则，采用模块独立 schema，避免更改原 `projects.sqlite` v15；不声称复用目前没有抽出的通用迁移类。projectId/会话来源为软关联：项目删除后保留任务和来源快照，不产生跨库事务或级联删除远端数据。工作区不可用不删除远端任务。

worker 生命周期为未启动、就绪、停止接单、退出、恢复核对。main 唯一创建实例，确认旧写入者退出后才替换；Operation 持久登记成功后才返回 ID。状态消息带 worker 代次和对象序号，丢弃旧代次迟到消息。崩溃恢复把中断的准备标为 blocked，将已批准或运行中的操作标为 unknown 供核对。操作拒绝、过期、完成或进入待核对后释放已登记的私有输入快照，并保留历史元数据和清单。启动时重新处理遗留的已登记快照。未过期的审核继续使用原快照。写操作不会因 worker 重建重发；本机 SSH 退出也不证明远端提交器或作业停止。

退出流程先完成设置草稿和远端 approved/running/unknown 操作的全部可取消确认，再停止接单、记录未决状态、关闭本机受管连接和数据库；取消退出时两套服务均保持可用。只清理精确登记的本机 SSH/传输进程及其启动身份，不能 blanket kill。受控 root/jump wrapper 在 exec 前写入本机 PID/启动身份记录；main 在 worker 退出后清理这些记录指向的精确 SSH，再允许替换，身份不匹配则保留证据并拒绝信号和重建。远端计算继续运行，停止本机传输/观察不会生成 scancel。

主进程复用精确窗口/frame/file URL 信任检查；preload 只开放有界的远端管理方法，不提供任意 exec/通用 SSH API。renderer 不读私钥、不启动 ssh。远端文本、文件名、进度和日志均作为不可信数据展示，限制 JSON/单行/响应大小、剥离终端控制序列，不当 HTML 渲染，不作为新的 Agent 指令自动执行。

默认观察策略：选中运行任务约 5 秒看一次有界日志/指标，按服务器合并的队列查询约 15 秒，后台降至 30–60 秒；遵守集群限制，可调整并指数退避/加入抖动。每台服务器限制并发，休眠唤醒合并补查，不补发积压的所有轮询。日志按文件身份与 offset 增量读取，识别截断/轮换；本地默认只保留有界尾部缓存，完整日志仍在远端并由用户选择下载。能力探针不跟随每个刷新重复运行。

关闭窗口沿用 macOS 既有应用生命周期；退出 Pi Hub 或电脑休眠后，本机观察暂停。Slurm 作业继续按调度器运行，Linux 受管任务仅在已确认服务器登录退出保留策略允许时承诺继续；不能把 setsid 成功当成该保证。重开按持久状态重新查询，不靠本机定时器证明任务活着。退出时提醒尚未完成的传输/提交，保存结果待核对状态并安全断开；不把退出 Hub 解释为 scancel。首期没有应用退出后仍推送状态的后台 daemon 或云端服务。

## 9. 本地接口与交付

实现入口为 `src/remote/`、`src/desktop/remote-{background,utility}.ts` 和 `src/renderer/remote-workspace.tsx`。本机输入读取/结果发布由 N-API 的 openat/O_NOFOLLOW 描述符边界完成；仅规则化路径字符串不足以抵御祖先目录替换。结果默认原子创建新目录；显式替换同时绑定父目录身份和整个原目录版本，原目录保留在私有 `.pi-hub-result-*` 路径。递归清单上限 10000 项/1 TiB，SSH 控制请求及响应上限 8 MiB、Agent/GUI socket 请求 128 KiB；字节走流式 SFTP；不支持的文件或超限直接失败，不截断后称成功。

SSH 配置文件需为不超过 64 KiB 的普通文件。默认主文件预览支持显式别名、同一 `Host` 行中的多个显式别名、`Host *` 默认项，以及 `IdentityFile` 和 `CertificateFile` 的 `~/` 路径。`HostName` 和 `User` 必须能从这些静态声明取得，`ProxyJump` 只解析已声明的别名。默认预览跳过 `StrictHostKeyChecking` 和 `UserKnownHostsFile`，导入的服务器使用 Pi Hub 的逐跳主机公钥核对流程。预览列出需要手动核对的别名，并标记未读取的 `Include` 与未解析的 `Match`、其他 `Host` 通配模式。文件选择和粘贴入口仍使用显式单别名、带完整 `HostName` 和 `User` 的静态片段。读取与预览阶段只处理配置文本和身份路径，无网络连接或私钥内容读取。

`IdentityAgent` 支持 `none` 与显式 `SSH_AUTH_SOCK` 环境引用。连接时校验当前自有 socket，用户选择 Agent 时还须从该自有 Agent 明确选择公钥。连接使用逐跳生成的公钥 `IdentityFile` 配合 `IdentitiesOnly`，仅尝试获选身份。需要交互认证时停止自动重试，由用户修复后手动检测。跳板配置和主机公钥逐跳保存，变更提升 Server revision 并废弃旧审批。

任务使用前台 argv。环境允许 LANG、LC_ALL、OMP_NUM_THREADS、MKL_NUM_THREADS、OPENBLAS_NUM_THREADS、CUDA_VISIBLE_DEVICES、NVIDIA_VISIBLE_DEVICES、TOKENIZERS_PARALLELISM。Slurm 资源允许 partition/account/qos/minutes/memoryMB/cpus/gpus/nodes；不提供任意 sbatch 选项。Linux 线程/GPU 选择不声称具备硬配额。输出通过 PI_HUB_OUTPUT 指定，输入目录是工作目录。

CLI 运行时为经 GUI 检测的绝对 Node 24+。`dist/remote/cli.mjs`、独立 `acceptance-cli.mjs` 以及所需远端资源精确 ASAR 解包为真实文件，由 profile 私有启动器绑定 CLI 实路径/字节摘要、Node 实路径/字节摘要和 canonical profile。普通 Node 不执行 ASAR 虚拟路径；无 PATH、仓库或其他 profile 回退。Python 入口在 ASAR 与精确解包集合中保持相同字节，编译 worker 和独立验收工具固定资源哈希，上传前核对；native 文件按 N-API 规则解包并核对。构建回执绑定输入与完整运行资产，双架构自动验包校验实际解包 CLI、资源集合和 native CPU。Unix socket 路径过长时 GUI 仍可工作，CLI 设置明确不可用；不创建公共临时目录回退 socket。

私有启动器参数为 `--grant-file /absolute/grant.json`，令牌不进入 argv。`server list|capabilities` 返回授权服务器摘要；`task status <attempt>`、`task logs <attempt> <offset> <length>`、`operation status <request>` 查询有范围的本地观察；日志长度上限 32768。`task adopt <task> <ref-json>` 只登记最近观察到的外部身份；`task prepare <request> <action-json>`（兼容 `prepare`/`propose`）产生 GUI 审核，不产生 Agent 自批。`list` 是兼容的有范围工作区快照。grant 最长 24 小时，可撤销，消费审批时再次核对。Hub 停止后 CLI 返回不可用，不创建数据库写入者。CLI 不依赖任何 Skill。

## 10. 能力验收与当前验证边界

本契约定义 M1/M2/M3 的完整范围；实现与验证状态分别记在[验证记录](validation.md)，不能把本契约正文当成运行验收证据。真实 Linux 退出最后登录后的保留策略和 Slurm controller 取消必须有授权环境验收，本次未提供。未验收能力默认拒绝，界面说明原因。

远端私有根的 `linux-capability.json` / `slurm-capability.json` 使用唯一契约 **schema=1**（不是 schemaVersion），绑定 host/user/bootId、supervisorHash、toolHash、evidenceDigest、evidenceFile 和 expiresAt。工具和读取端都将有效期限制在一天内。toolHash 覆盖发送到远端的完整 Python 入口。evidenceDigest 是原始结构化证据规范 JSON 的 SHA-256，不是对同一远端账户的密码学认证。更换主机/启动代次/监督器/验收工具，证据缺失或改动，以及到期均关闭能力。

独立可执行验收工具源码为 `src/remote/acceptance-cli.ts` 和 `acceptance.py`，构建为精确解包的 `dist/remote/acceptance-cli.mjs`；GUI 检测 Node24+ 后创建当前 profile 私有 `pi-hub-remote-acceptance` 启动器，绑定工具与 Node 实路径及摘要。它不消费 Agent grant、不写本机业务数据库，也不提供手填通过值。只有明确授权合成资源、逐跳已核对的静态 server 文件、新建且不覆盖历史的证据目录，才能开始远端检查。工具只创建本次随机票据、合成工作负载和唯一标记作业；保存原始命令、回执、身份、观测及清理记录。未执行、失败、环境不支持或清理未确认时不发布能力。

Linux 检查 lastLogout、termTree、killTree、reapersECHILD、crashNoReplay、mainExitRace、helperLossUnknown、staleIdentity。检查包括实际 wait/ECHILD、主程序先退出而孤儿继续运行、helper 异常丢失、自然退出/TERM/KILL 竞态、持久动作断点和旧 helper/endpoint 身份拒绝。lastLogout 必须指定已知延迟清理政策窗口 30–3600 秒，实际基线 SSH logind 会话退出后连续整个窗口无其他登录且控制者存活；无 logind、仍有别的登录、政策未知或更长均不算通过。不退出其他用户会话、不修改 PAM/logind。真实 PID/PGID 数字回绕不强制制造，旧启动身份拒绝覆盖相同数字但不同代次；原始证据保留实际测试范围。

Slurm 检查 controllerFilters、jobIdReuse、ownerMismatch、clusterMismatch、uniqueName。通过 controller 的 `scontrol show config` 与 `ping` 绑定实际版本/cluster/配置摘要，不用本地 `scontrol --version` 冒充。工具提交三个唯一命名的合成 sleep 作业，其中一个在显式授权且可达的第二 cluster。用错配的名称、另一自有作业 ID、错误 owner 和第二 cluster 的活动作业检查过滤，再确认目标作业取消与全部清理。jobIdReuse 是旧 marker 与另一活动自有 ID 的约束反例，不伪称强制真实计数器回绕。`--cancel-mode sluid` 使用实际查询到的稳定标识作为 scancel 的位置参数；默认 constraints 使用完整 ID 加 `--ctld`/owner/cluster/name。缺第二 cluster 或对应 controller 能力时不发布通过记录。

### 授权环境中的执行步骤

1. 建立独占测试账号/工作根，明确授权 SSH 最后登录退出、合成 Linux 工作负载或 Slurm 提交/取消，以及第二 cluster。GUI 逐跳核对候选指纹并保存服务器，在「能力验收要求」展开静态配置，写入本任务私有绝对路径 server.json。开发本身无权访问用户真实服务器、配置、私钥、对话、凭据或研究输入。
2. 在 GUI「Agent CLI」检测明确 Node24+，使用显示的私有验收启动器。Linux 示例参数：`--authorize-owned-resources --server-file /absolute/server.json --evidence-dir /new/evidence --logout-window-seconds 60 --publish`；60 只有在覆盖该授权主机的已知政策时才可使用。Slurm 参数另为 `--authorized-mismatch-cluster explicit-cluster --cancel-mode constraints`，不传 Linux 窗口。
3. 查看新目录的 invocation/start/raw-evidence/result/published-receipt。失败运行保留；若需要继续查询，使用新证据目录与 `--resume-token token`，仍须显式授权和相同已核对配置。不把 help、语法、argv 夹具或修改布尔值当作通过。
4. 成功发布后在 GUI 重新检测。探针独立重验 Linux prctl/waitid 或 Slurm controller 身份；记录只能开启实际已验的对应能力。整体功能还须独立复核原始证据，工具自报不是产品验收。

真实 Linux 最后登录保留、内核生命周期及 Slurm controller 全矩阵目前没有授权环境可运行，见[验证记录](validation.md)。本机合成 SSH/SFTP、文件系统、CLI 和 quiet Electron 检查分别报告；可执行工具已提供与真实环境未验证是两个不同事实。所有开发保持自有 profile、密钥、known_hosts、sshd 与合成文件；不安装应用、不修改全局配置、不引入生产测试钩子。更新功能继续暂缓。
