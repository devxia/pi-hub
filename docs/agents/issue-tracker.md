# 本地任务跟踪

规格和任务保存在本机被 Git 忽略的 `.scratch/<feature-slug>/`，不随仓库分发，不自动向远程平台发布。有效长期规则必须合并到受跟踪的当前文档。

## 活跃任务

- 实施规格为 `spec.md`；拆分任务为 `issues/<NN>-<slug>.md`，编号在该功能内稳定，按 `Blocked by:` 而非编号执行。
- 顶部记录 `Status:`（[分类](triage-labels.md)）、`Execution: todo | in-progress | done` 和 `Blocked by:`；无依赖写 None。
- 只有依赖已完成才实施；验收写清实际版本、范围、失败与限制。分类 ready-for-agent 不等于实施完成。
- 讨论产生新决定后立即更新完整正文和依赖，不追加一份互相冲突的规则。必要说明保留当前成立理由，不以流水账替代有效规格。

## 完成与整理

完成后把有效产品规则、架构理由、设计和测试约束合并到 docs/ 及根目录规范，验证结果归入版本化验证入口。随后删除被替代的规格、issue、提案、决策地图和阶段说明，避免形成多套产品契约。文档只保留最终一致的完整内容；受跟踪文档由 Git 提供修改追溯，本机 `.scratch` 不再依赖 Git 留存。无需在受跟踪工作树复制旧决定。

原始 JSON/log/截图/TUI 是特定运行的数据，按版本保留，不作为现行需求。整理删除项和内容去向可记录在机器清单，不复制被删除的决定正文。不要无授权批量清理实际用户数据或测试事实。

## Skill 对接

skill 要求发布任务时创建上述本地文件；读取任务时使用指定路径，仅给编号则在对应功能目录查找。to-tickets 的已批准任务使用 ready-for-agent。若使用决策地图，仍在同一功能目录记录依赖及当前答案；决定完成后按本节合并，不能留下第二套有效规格。
